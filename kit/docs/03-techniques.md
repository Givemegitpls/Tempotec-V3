# 03. Приёмы реверса и патчинга

## 3.1. Адреса

`VA = p_vaddr + (file_offset - p_offset)`. У V3 — `VA = file_offset + 0x400000`.
Всегда проверяй по `readelf -S/-l`; для MIPS-ELF это критично, ошибка на 0x10000
уводит на чужой код (в NOTES это уже ловилось: `0xaae114` vs `0xabe114`).

## 3.2. Поиск строк и xref в MIPS

- Строки — в `.rodata`, часто **не** адресуются напрямую, а лежат в таблице
  запросов; код берёт строку по индексу. Поэтому «Ghidra не нашла xref» ≠ «код
  не используется». Ищи запись в таблице (у V3 база `0x9b7730`, шаг 4 байта).
- Прямая загрузка vaddr: пара `lui $reg, HI(va)` + `addiu/$reg, LO(va)` (LO со знаком)
  или `ori`. `tools/generic/xref.py` ищет такие пары по подстроке.
- Быстрый disasm без Ghidra: `tools/generic/disasm_range.py` (capstone,
  `md.skipdata = True` — иначе дизасм обрывается на первом неверном слове).
- Косвенные вызовы (`jalr` через vtable/слот) статически не видны — смотри таблицы
  коллбэков и `find_jal.py`.

## 3.3. Виды патчей

**На месте (0 риска сдвига).** Меняешь байты/константу/строку той же длины:
- константа в `addiu/slti/ori`;
- символ/строка равной или меньшей длины (хвост добить нулями).

**Перенос строки.** Если новая строка длиннее: положить её в свободный хвост
`.rodata` (у V3 `0x93f610`, ~1.7 КБ безопасного места) и переписать указатель в
слоте таблицы либо пару `lui/addiu` в коде. Образец — `tools/examples/patch_sql.py`.

**Новый код (RX-запас / code cave).**
- Определи запас: `readelf -l`, конец RX-сегмента и начало следующего. У V3 зазор
  `0x67e370..0x67f000` (VA `0xa7e370..0xa80000`), расширяешь `p_filesz/p_memsz`.
- Пиши код в запас, из точки вызова — `jal <VA>` (direct call; в этом `.text`
  region `jal` работает). Ассерти оригинальные 8 байт точки вызова.
- `jal` затирает `$ra`, поэтому хук не должен предполагать старый `$ra`; если
  оригинал на него опирается — восстанавливай из стека/регистра, сверяй дизасмом.

**Трамплин (вход в функцию).** Заменить первые инструкции на
`lui $at,HI; ori $at,LO; jr $at; nop` (`jr` не трогает `$ra`), хук доисполняет
перезаписанные инструкции и уходит `j` в продолжение. Сложнее — прибегать только
если хук обязан быть на входе (вызовы косвенные, как у источников видов).

## 3.4. Медиатека: SQL-строки, списки, кэш

- Запросы — текстом в `.rodata`; есть таблица строк и таблица шаблонов вставки
  (`INSERT INTO %s%d VALUES (...)`, `list_tb_`). Один литерал может обслуживать
  несколько мест (`lui`-пары) — меняй **все** ссылки согласованно.
- `list_tb_N` — кэш строк списка; наполняется несколькими `INSERT`-ветками подряд
  (например, для песен артиста: файлы / cue-CD / cue-трек). Патч одной ветки при
  живых остальных = «плавающий» мусор между открытиями — меняй все ветки.
- `MANAGER_TABLE` (path→id/count) хранит, какой `list_tb_N` соответствует ключу.
  Без её сброса плеер переиспользует старый кэш.
- Для сортировки списков с алфавитной полоской таблицы обязаны идти в порядке
  `character` (полоска считает позицию как «число записей до буквы»).

## 3.5. Виды, данные, обложки (V3)

- Таблица видов `0x95e770` (запись `0x3c`): `w2` — селектор шаблона (`@class@`/
  `@music@`), `w4`=bit0 — включает фоновый загрузчик обложек, `w13` трогать
  нельзя, ключ — `view+0x3de0`, тип — `view+0x40`.
- Источник данных вида — коллбэк `view+0x423c` (из таблицы путей `0xabd3c8`);
  подмена одного слова-указателя в этой таблице меняет источник (метод A).
- Список строк — постраничный (страницы по 16, запись `0xa88`); получить строку:
  `FUN_0045e9a0(list, idx)`.
- Обложки: `FUN_004a52a0` заполняет cover-запись (0x948) из строки списка;
  `cover+0x114` — путь (wide), парсер `FUN_004ca500` ищет по нему файл/папку
  (`front/cover/folder`), требуя у имени аудио-расширение. `+0x524` — только
  проверка стриминг-префикса (`qobuz_/tidal_`), не источник пути.
- `cover+0x114` для видов-каталогов разрешается запросом по колонке `id`
  `MEDIA_TABLE` — поэтому в строку списка надо класть настоящий `id`, а не rowid/0.

## 3.6. Алфавит и мультиязычность

- Полоска — картинка `a_z.png`; буква записи хранится в колонке `character`
  таблиц. Плеер сам пересчитывает `character` при сканировании (в т.ч. триггерами),
  поэтому правки живут в БД.
- Прыжок по букве = «число записей с `character` меньше буквы» → список обязан
  быть отсортирован по `character`; записи, начинающиеся не с A–Z (цифры/символы),
  уезжают в конец под `#` (маркер должен быть **больше** `z`, у нас `~`, т.к.
  сравнение идёт `COLLATE NOCASE`).
- Логик две: у сущностей (артисты/альбомы/жанры) буква = транслит кириллицы в
  латиницу; у треков — первая буква **названия**. Держи их раздельно.
- Артикли (`The`, `Der`, `La`, …) и ведущие символы в стоке не срезаются. Это
  можно добавить **в наш DB-пайплайн** (вычисление `character`), не трогая бинарь.
  Бинарный Sorting Patch от hiby-mods — адреса R3 Pro II, к другим устройствам
  «как есть» не переносится.

## 3.7. Диагностика без падений

- **RW-маркеры/буферы** — можно; **RX-запись** — гарантированный краш. Логи — через
  существующую лог-функцию плеера (например `FUN_004716c0`) из main-thread кода.
- Не трогать `view`/контроллеры из таймер/cover-потока (non-main-thread) — крашится.
- `strace`/дампы `/proc/pid/mem` — снаружи, без правок бинаря (самый безопасный
  способ увидеть, что реально происходит).
- Дамп heap: читать кусками по 2048 страниц с ровными базами; wide-строки искать
  `a\x00:\x00`; записи — по полям (`+0x114` wide, stride `0x948`).
