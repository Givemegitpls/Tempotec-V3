# 01. Устройство прошивки HiBy OS

## Формат `.upt`

`.upt` — это **ISO9660** образ. Внутри:

| файл | что это |
|---|---|
| `SYSTEM.UBI` | UBI-образ корневой ФС (UBIFS) — сюда попадают все правки |
| `UIMAGE.BIN` | ядро (обычно не трогают) |
| `UBOOT.BIN` | загрузчик (не трогают) |
| `UPDATE.TXT` | манифест с **md5** разделов (`rootfs=...`) — обязателен для прошивки |
| `VERSION.TXT`, `_GITIGNO` | служебные |

Распаковка/сборка (всё в docker, в систему ничего не ставится):

```
7z x -y stock.upt -o unpacked               # ISO
ubireader_extract_files -k -o SYSTEM unpacked/SYSTEM.UBI   # корневая ФС (нужен root: симлинки/device-ноды)
mkfs.ubifs -x lzo -d SYSTEM -e 0x1F000 -c 480 -m 0x800 -o SYSTEM.UBI
genisoimage -l -o out.upt SYSTEM.UBI UIMAGE.BIN UBOOT.BIN UPDATE.TXT VERSION.TXT _GITIGNO
```

После пересборки `SYSTEM.UBI` **обязательно** пересчитать md5 в `UPDATE.TXT`
(блок `rootfs={...}`). Это делает `tools/generic/fix_update_md5.py`.

## Что где в корневой ФС

- `/usr/bin/hiby_player` — основной бинарь: UI (litegui) + медиатека (SQLite).
  MIPS32 little-endian, stripped, ~7 МБ. Все строки запросов лежат текстом в
  `.rodata`, прямой адресации из кода почти нет — строки берутся по **индексу**
  из таблицы.
- `/usr/resource/litegui/themeN/...` — картинки (в т.ч. алфавитная полоска
  `touch_list/a_z.png`).
- `/etc/init.d/` — busybox init (systemd нет). Rootfs в стоке ремонтируется в rw
  (`mount -o remount,rw /`) — можно менять файлы на живом устройстве.
- `/data/usrlocal_media.db` — медиатека, **отдельный раздел** (`/data`), прошивкой
  не перезаписывается. Здесь же кэш списков (`list_tb_*`, `MANAGER_TABLE`).

## Адресация бинаря

Для MIPS ELF извлекаем из program headers: `VA = p_vaddr + (file_offset - p_offset)`.
На практике у этих устройств `VA = file_offset + 0x400000`, но **проверяй по
секциям** (`readelf -S`) — не полагайся на константу вслепую.

Свободное место для нового кода:
- **RX-запас** — зазор между концом RX-segment (`p_filesz`) и началом следующего
  сегмента (у V3: `0x67e370..0x67f000`, VA `0xa7e370..0xa80000`). Расширяешь
  `p_filesz/p_memsz` RX-сегмента до начала следующего.
- **code cave** — длинные нулевые прогоны в `.text` (у других устройств, напр.
  R3 Pro II, `~0x41b8b0`).

Оба варианта — «дописать код в конце файла/в дырке, не сдвигая offsets».

## Медиатека и списки (важное для UI-фич)

- Строки SQL-запросов лежат в таблице: база `0x9b7730` (V3), индекс =
  `(VA - base)/4`, ~199 записей. Перезапись указателя в слоте = подмена запроса
  **без переноса кода**.
- Таблицы списков (`list_tb_N`) — кэш строк вида. Ключ → индекс списка и счётчики
  хранит `MANAGER_TABLE` (path→id/count). Плеер переиспользует кэш, поэтому после
  смены логики списка его надо сбросить.
- Виды (listviews) описаны таблицей `0x95e770` (V3): запись `0x3c` байт, поля —
  имя, тип (`view+0x40`), селектор шаблона, флаги (`w4`=bit0 включает фоновый
  загрузчик обложек), ключ (`view+0x3de0`).
- Обложку рисует фоновый парсер; данные записи обложки заполняет `FUN_004a52a0`
  (см. `docs/04-recipes.md`, рецепт A).

## ADB

- У части прошивок adb включается easter-egg'ом (R3 Pro II: тап по «About» 10 раз).
- У V3 Analog — скрипт `/etc/init.d/S98adb_debug` в отладочном образе (канал живёт
  первые ~3 минуты после включения; при отвале `adb kill-server`).
- Устройство видно как `TempoTec V3`; root-shell есть.

## Совместимость устройств

Один формат `.upt` и один класс SoC (Ingenic X1600E) у: R1, R3 II 2025, R3 Pro II,
Tempotec V1/V3. Прошивки и адреса у каждого свои — переносить патчи только с
пересчётом адресов (`docs/06-adapt-new-device.md`).
