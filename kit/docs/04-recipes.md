# 04. Рецепты (Tempotec V3 Analog)

Ниже — как воспроизвести фичи на V3. На другом устройстве адреса другие:
пересчитай по `docs/06-adapt-new-device.md`, логика та же.

База: релизный бинарь `4429784b…` (сток + `patch_player` + `patch_sql`). Порядок
скриптов важен. Проверка состава — `--check` у каждого.

## Рецепт A. Обложки в «Artists → артист → список альбомов»

**Проблема:** верхний уровень «Albums» умеет обложки, а «альбомы артиста»
(вид `vg_listview_albums_of_an_artist`, idx 21) — нет; строки списка ещё и
дублировались/не открывались.

**Идея:** назвать подменённый вид как «Albums» (`vg_listview_album`), зажечь флаг
`w4` (парсер обложек), дать строкам реальный путь и настоящий `id` MEDIA_TABLE.

Цепочка (`tools/examples/`):

| # | скрипт | что делает |
|---|--------|-----------|
| 1 | `exp_album_view.py` | `0x4a8b84`: вид-21 → `vg_listview_album` (подмена имени вида) |
| 2 | `exp_flags_view21.py` | `w4=1`, `w5=1` у вида 21 (`0x55ec6c/0x55ec70`) — включает поток обложек |
| 3 | `exp_coverpath_combo.py` | RX-шаблон `INSERT INTO list_tb_N` (0xa7e800) с колонкой `path` = подзапрос; ссылки `lui/addiu`; `phdr2 → 0x67f000`; источник пути `0x4a5528 → col1` |
| 4 | `exp_cover_kind9col.py` | слот `0xABE114 := 0x4A9180` (kind9) + `col3 = ?2` |
| 5 | `exp_cover_kind9id.py` | `col0 = (SELECT id FROM MEDIA_TABLE WHERE album=?2 LIMIT 1)` — обложка **своего** альбома |

Ключевые факты (полностью — `reference/NOTES-v3.md`):
- `cover+0x114` (wide-имя) — источник пути для парсера `FUN_004ca500`; `+0x524` —
  только признак стриминга.
- `FUN_004a52a0` строит cover-запись из строки списка (`FUN_004369a0(view+0x3de0)`),
  путь разрешается запросом к `MEDIA_TABLE` по колонке `id` строки.
- Если `col0` у всех строк = 0 (сток kind9-шаблона) → одна картинка на список;
  `MIN(rowid)` даёт случайные; нужен именно `id` MEDIA_TABLE.

## Рецепт B. Фильтр альбомов по `album_artist`

**Проблема:** список альбомов артиста фильтровался по тегу трека `artist`, который
хранит склейку (`"Дэн Субботин;Green Crow"`), а «Артисты» строятся из
`album_artist`. Итог — пустые списки/мусор у авторов с фитами.

**Правка:** строка VA `0x9c284c` переписывается **по месту**:
```
было:  SELECT DISTINCT album FROM MEDIA_TABLE WHERE artist like ? ORDER BY album collate pinyin
стало: SELECT DISTINCT album FROM MEDIA_TABLE WHERE album_artist like ? ORDER BY album
```
Скрипт `tools/examples/exp_albums_by_album_artist.py` (идемпотентный, `--check`).

Данные реальной БД: `artist` со `;` — 17 строк, `album_artist` — 0; у 3 артистов
альбомы были только по `album_artist`; потерь нет.

## Рецепт C. Кириллица в алфавитном поиске (БД)

Полоска стоковая A–Z + `#`, не перерисовываем. Правки живут в медиатеке:

1. `tools/examples/translit_db.py` — проставить `character`: у сущностей транслит
   кириллицы в латиницу; у треков — первая буква названия; всё не-A–Z → `~` (в
   конец). Плюс триггеры `fix_char_*`, чтобы новые записи скана получали букву.
2. `tools/examples/reorder_db.py` — пересобрать таблицы списков `ORDER BY character,имя`.
3. `tools/examples/album_artist_db.py` — `ARTIST_TABLE` = авторы альбомов
   (`ALBUM_ARTIST2_TABLE`), чтобы «Артисты» совпадали с источником альбомов.

В прошивке вызывается `tools/examples/patch_sql.py`: сборка списков приводит букву
к `A–Z` (`#' → `~`, сортировка `ORDER BY 3,имя`), слот 125 берёт артистов из
`ALBUM_ARTIST2_TABLE`, и 26 мест сортировок переведены на `ORDER BY character`.

Порядок: `translit → reorder → translit` (reorder пересоздаёт таблицы и сносит
триггеры!).

## Рецепт D. Дедуп и клики по альбому (важные предупреждения)

- Дедуп «в лоб» правкой одной `INSERT`-ветки kind5 (`GROUP BY`) **не работает**:
  кэш собирается циклом из нескольких шаблонов — см. `docs/05-pitfalls.md`.
  Рабочий путь (в релизе) — источник kind9, который уже отдаёт по одной строке на
  альбом.
- Клик по строке строит ключ следующего вида из поля записи
  (`FUN_004a7500` → `FUN_0049d6e0`). Для подменённого вида проверяй, что ключ
  собирается из имени альбома (col3), а не трека. Хуки в клик-путь ставить только
  после проверки main-thread контекста.

## Рецепт E. Обратимый shuffle (случайный порядок)

**Проблема:** в режиме random «вперёд» каждый раз выбирал следующий ещё не
сыгранный трек и пропускал уже проигранные, а «назад» просто двигал курсор → после
«назад» вернуться вперёд было нельзя.

**Механика:** `FUN_0042da00` (режим `DAT_00b03bf4 == 2`) использует таблицу-перестановку
`DAT_00b03cbc` (`{индекс, флаг "сыграно"}`), курсор `DAT_00b03cc0`; перестановку
строит `FUN_0042d720` (Fisher–Yates на libc `rand`, сид — `/proc/sys/kernel/random/uuid`).

**Правка:** в random-ветке «вперёд» убрать пропуск сыгранных —
`0x42dd8c: bne $v1,$zero,0x42dc3c` → `nop` (`abff6014` → `00000000`).
Скрипт `tools/examples/exp_shuffle_linear.py` (идемпотентный, `--check`).

**Защита от выхода за диапазон:** при смене списка (граница альбома, `album_skip`)
таблица шафла/индекс остаются от прошлого списка → индекс улетает и плеер виснет.
Хук на `FUN_0042da00` (`0x42da2c` → RX `0xa7e370`, скрипт
`tools/examples/exp_shuffle_guard.py`): если режим random и размер таблицы
`DAT_00b03cc4 != DAT_00b03bfc` → сбросить `DAT_00b03c04` и вызвать
`FUN_0042d720(count,1)` (пересборка). При совпадении размера хук прозрачен, поэтому
выбор трека не ломается.

Результат: «вперёд»/«назад» двигают курсор по одной перестановке → «назад → вперёд»
возвращает тот же трек; порядок случаен, без повторов до конца списка; при смене
списка состояние сбрасывается; режимы order/loop/single не затронуты.

## Рецепт F. Самодостаточная медиатека (бинарь сам правит БД)

Цель: после «обновления медиатеки» плеер **сам** приводит БД в порядок
(буквы/порядок, разбор `artist` по `;`) — без компьютера и внешних скриптов.

Идея: положить SQL-фикс файлом в образ и научить бинарь выполнять его в нужной
точке. SQL выполняется через `sqlite3_exec` (`FUN_005f0be0(db, sql, 0, 0, err)`),
где `db` = тот же handle, что идёт в `commit transaction` (регистр `a0` в точке
хука; `FUN_0070eb00` берёт его как `0x98(scanctx)`, НЕ как `*(*(0xbc18f0))`).

Состав:
1. `tools/make_db_fix_sql.py` → `fw/SYSTEM/usr/share/hiby_db_fix.sql` —
   идемпотентный SQL: таблица `CYR_MAP` (кириллица→латиница), `ARTIST_SPLIT_NUM`,
   триггеры `fix_char_*`/`fix_char_upd_*` (буква: транслит, A-Z, иначе `~`; у
   треков — по названию), `split_ARTIST2_TABLE`, одноразовый разбор склеек,
   починка существующих записей и пересборка таблиц списков по `character`.
   Держать компактным (~9.6 КБ): большой CASE в каждом триггере (24 КБ)
   перешагивает LEB и растит образ. Вшивается в образ шагом `make.sh build`.
2. `tools/exp_db_autofix.py` — хук: на `0x70ECFC` (`jal 0x6fbd80` «commit
   transaction» в пересборке `FUN_0070eb00`) читает файл сырыми syscall'ами
   (open=4005/read=4003/close=4006; буфер — `malloc`/`free`) и выполняет его. Все
   вызовы из RX — через `jalr` (см. `05-pitfalls.md` п. 21).

Проверенная точка — `0x70ECFC` (после `commit`, БД свободна; общая точка схода
всех веток `FUN_0070eb00`, единственный вызов — `0x7113d8` из `FUN_007112a0`,
воркер «обновления медиатеки»). Точки, которые НЕ использовать: `0x71D0B0`
(«Scanner stopped») — это FM-**радио** seek-сканер, при «обновлении медиатеки» не
исполняется; `0x4E980C` (эпилог `FUN_004e97c0`) — общая функция ожидания,
вызывается и при подключении USB — плеер вешается (п. 23).

Проверка на устройстве: прошить → «обновление медиатеки» → в БД 18 триггеров,
`ARTIST_TABLE` без склеек, `MEDIA_TABLE` без «сырых» букв, порядок по `character`,
integrity ok. Offline-репетиция — `tools/verify_build.py --db <копия базы>`.

Сборка образа: `overlay/` (adb-скрипт по маркеру `/mnt/sd_0/enable_adb`) +
`make.sh build` (dedupe дубликатов + `chmod 775` на бинарь).
