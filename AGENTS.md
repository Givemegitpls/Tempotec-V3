# AGENTS.md — Tempotec V3 Analog (мод прошивки)

Правила для агентов, работающих в этом репозитории. Технические детали и грабли —
в `.opencode/NOTES.md` (читать перед правками), статус и план — в `todo.md`,
пользовательское описание — в `CHANGELOG.md`.

## Экономия контекста (обязательно)

1. **Источник правды — файлы, не чат.** В начале сессии прочитать `todo.md` и
   `.opencode/NOTES.md`; в конце — дописать туда результат (статус, находки).
   Чат одноразовый, файлы переживают сессии.
2. **Тяжёлый реверс — только через субагентов** (`explore`/`general`):
   декомпиляции, дизасм, дампы, простыни `--check` не тащить в основной контекст —
   только выводы. Артефакты складывать в `work/` и ссылаться путём.
3. **Фильтровать вывод команд** (`head`/`tail`/`grep`/`cut`); файлы читать
   фрагментами (`offset`/`limit`) и через `grep`, не целиком.
4. **Одна сессия — одна задача.** При росте истории — компакция/новая сессия,
   предварительно записав состояние в `todo.md`.
5. **Скиллы вместо пересказа** (`tempotec-fw-mod`, `tempotec-fw-docker`,
   `archive-7z` и т.д.) — обновлять их, а не повторять знания в чате.
6. **Не вставлять в чат большие диффы/логи/дампы** — сохранять в файл и
   цитировать короткую решающую строку.

## Трекинг изменений и защита от регрессий

1. **Один патч — одна итерация.** После каждого — проверка (см. п. 3) и только
   потом следующий патч. Каждый скрипт правки идемпотентен и имеет `--check`.
2. **Манифест сборки.** Для каждого образа фиксировать: md5 бинаря, список
   применённых патчей (вывод `tools/*.py --check`), md5 SQL/файлов, md5
   ISO/UBI. Хранить рядом с образом/в `CHANGELOG.md`.
3. **Проверять ДО флеша:** все `--check`, целостность образа
   (`tools/make.sh verify`), offline-симуляция правок БД на копии реальной
   базы (инварианты: число триггеров, склеек 0, «сырых» букв 0, порядок по
   `character`). Бутлупы и порча БД ловятся здесь.
4. **Чек-лист регрессий на устройстве** (фиксированный): Artists / «Исполнитель
   альбома» / Albums / All / Files; соавтор (`Дэн Субботин`); пустой список →
   «awaiting scan». Ожидаемые значения — из копии реальной БД.
5. **Откат всегда под рукой.** Держать known-good бинарь/образ; возврат —
   `adb push` рабочего бинаря + `reboot` (секунды).

## Технические константы (кратко)

- Все операции с прошивкой — только через docker: `./docker/fw.sh <cmd>`.
- Пайплайн: `./tools/make.sh {unpack|patch|build|verify|all} [имя образа]`.
- Базовый бинарь — `4429784b…` (не затирать случайными сборками).
- `jal`/`j` из RX-зоны (`0xa7e370..0xa7f000`) уходят не туда (верхний ниббл PC) —
  вызовы из RX делать только через `jalr`.
