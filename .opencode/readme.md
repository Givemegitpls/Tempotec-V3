# Tempotec V3 Analog — пайплайн сборки (технический документ)

> Документ для агентов и разработки. Человекочитаемое описание мода, инструкции по
> установке и краткая сборка — в корневом `README.md`. Здесь — подробности
> пайплайна, ручная распаковка/упаковка и список готовых образов.

Здесь — как собрать и прошить нашу прошивку. Что именно в ней изменено (простыми
словами) — в `CHANGELOG.md`; технические подробности — в `NOTES.md` и `docs/`.

Готовые образы лежат в `out/`, откатные копии — в `backup/`.

## Сборка одной командой

**Что нужно:** Linux, установленный `docker` и стоковая прошивка `v3_analog.upt`
в корне проекта (уже лежит). Больше ничего ставить в систему не требуется — все
инструменты (7z, ubi_reader, mkfs.ubifs, genisoimage) живут в docker-образе.

**Шаги:**

1. Собрать docker-образ с инструментами (один раз):

   ```
   docker build -t tempotec-fw-tools docker
   ```

2. Собрать прошивку «с нуля» — из чистого стока, со всей цепочкой патчей:

   ```
   ./tools/build_all.sh
   ```

   По умолчанию результат — `out/v3_analog.upt`. Другое имя образа задаётся первым
   аргументом или переменной окружения `IMAGE`:

   ```
   ./tools/build_all.sh v3_analog_test.upt
   IMAGE=v3_analog_test.upt ./tools/build_all.sh
   ```

   Второй аргумент (необязательный) — копия базы медиатеки для офлайн-проверки
   вшитого SQL-фикса:

   ```
   ./tools/build_all.sh v3_analog_test.upt work/device/media.db
   ```

3. Забрать готовый образ:

   ```
   out/v3_analog.upt
   ```

   На SD-карту его нужно класть **строго под именем `v3_analog.upt`** — плеер ищет
   файл обновления именно с таким именем в корне карты.

Всё остальное скрипт делает сам: распаковывает сток в `fw/`, применяет базовые
патчи и всю цепочку правок бинаря, прогоняет проверки и собирает образ.

### Что происходит по шагам (для понимания)

- **1/5 распаковка стока** — `v3_analog.upt` (ISO) разбирается в `fw/unpacked`,
  из него достаётся `SYSTEM.UBI` и распаковывается в дерево `fw/SYSTEM`.
- **2/5 базовые патчи** — `tools/patch_player.py --album-level` (уровень альбомов
  у «Исполнителя альбома») и `tools/patch_sql.py` (правки SQL-запросов списков).
- **3/5 цепочка патчей** — по порядку `tools/exp_*.py` / `tools/patch_*.py`
  (обложки, полоска A–Z, переключатели, очередь по авторам, разбор соавторов,
  вшитый SQL-фикс, USB-режим ADB; порядок — в `tools/verify_build.py:CHAIN`),
  затем права `775` на `hiby_player`.
- **4/5 проверки до флеша** — `tools/verify_build.py`: прогон `--check` по всей
  цепочке патчей.
- **5/5 сборка образа** — `overlay/` копируется в дерево, генерируется вшитый
  `usr/share/hiby_db_fix.sql`, пересчитывается md5 в `UPDATE.TXT`, дерево
  упаковывается в `SYSTEM.UBI` и складывается в ISO `out/<имя>.upt`.

## Проверки перед прошивкой

```
python3 tools/verify_build.py fw/SYSTEM/usr/bin/hiby_player \
    --image out/v3_analog_my.upt --db <копия_базы.db>
```

Проверяет: права дерева, наличие вшитого SQL, все `--check` патчей, целостность
образа и прогон вшитого SQL-фикса на копии базы (триггеры, отсутствие «склеек» и
«сырых» букв, `integrity ok`).

Дополнительно:

```
./tools/make.sh audit              # что именно войдёт в образ (дифф дерева со стоком)
./tools/make.sh verify [имя]       # распаковать образ и сверить дерево/хеши/патчи
```
Имя образа: по умолчанию `v3_analog.upt`; иначе первый аргумент (`build|verify [имя]`)
или переменная окружения `IMAGE=...`; исходник стока — `SRC=...` (по умолчанию
`v3_analog.upt`).

## Установка на плеер

1. Скопировать собранный образ (`out/v3_analog.upt`) в **корень SD-карты** — строго
   под именем **`v3_analog.upt`** (плеер ищет файл обновления именно с таким именем).
2. Вставить карту в плеер.
3. На плеере: **Настройки → «Обновление ПО»** → выбрать файл прошивки.
4. После прошивки один раз выполнить **«Обновление медиатеки»** — прошивка сама
   расставит буквы, разберёт соавторов и пересоберёт списки (компьютер не нужен).

**Откат:** прошить стоковую `v3_analog.upt` (или известную рабочую сборку из
`backup/`) тем же способом.

## Состав образа

В образ попадают только:

- патченый `usr/bin/hiby_player`;
- файлы из `overlay/`;
- сгенерированный `usr/share/hiby_db_fix.sql` (вшитый фикс медиатеки);
- метки пункта USB-режима **ADB** в языковых файлах.

## Грабли

- **Права `usr/bin/hiby_player` = `775`.** Копия с правами `644` собирается, но
  плеер не стартует — бутлуп на заставке. `make.sh build` выставляет права сам.
- **Хеши `SYSTEM.UBI` и ISO невоспроизводимы** (таймстампы) — сверять надо md5
  самого бинаря и дерево, а не образ целиком.
- **Не перезаписывать базовый бинарь** `fw/SYSTEM/usr/bin/hiby_player` случайными
  сборками: это база для всех патчей (md5 `4429784b…`).
- `jal`/`j` из RX-зоны и пещер делать нельзя — только `jalr` (иначе плеер падает).
- Произвольная команда внутри контейнера с инструментами: `./docker/fw.sh <команда>`.

## Для реверса: ручная распаковка и упаковка

Ниже — исходная инструкция с форума (полезна, если нужно копаться в прошивке
руками, без нашего пайплайна).

Инструкция v3_analog.upt это ISO файл. Разобрать его можно просто в 7-zip

```
7z x v3_analog.upt
```

После распаковки имеем образ системного раздела SYSTEM.UBI, упакованное ядро
UIMAGE.BIN (которое никто из кастомизаторов не трогает), загрузчик UBOOT.BIN, и
"служебные" файлы UPDATE.TXT, VERSION.TXT, \_GITIGNO. Если какие-то из файлов
менялись при кастомизации (ядро и загрузчик обычно никто не трогает, потому речь
только о SYSTEM.UBI), то нужно пересчитать и изменить MD5 для нового SYSTEM.UBI
в файле UPDATE.TXT. Отредактировать файл можно вручную или командой

```
sed -i '7,$s/md5=.*/md5='"$(md5sum unpacked_fw/SYSTEM.UBI | cut -d\  -f1)/" unpacked_fw/UPDATE.TXT
```

Запаковать файлы обратно в v3.upt можно с помощью mkisofs / genisoimage :

```
genisoimage -l -o v3_analog.upt unpacked_fw/{SYSTEM.UBI,UIMAGE.BIN,UBOOT.BIN,UPDATE.TXT,VERSION.TXT,_GITIGNO}
```

Распаковка образа системного раздела SYSTEM.UBI в Linux (Владелец/группа файлов
и директорий 1004:1004 , я всегда правлю для замененных файлов. А может не
обязательно...) (для плееров HiBy 1009:1009)

```
sudo ubireader_extract_files SYSTEM.UBI -o SYSTEM -k
```

Упаковка SYSTEM в SYSTEM.UBI в Linux

```
mkfs.ubifs -x lzo -d SYSTEM -e 0x1F000 -c 480 -m 0x800 -o SYSTEM.UBI
```

где LEB Size: 126976 | max_leb_cnt: 480 | min_io_size: 2048

Чтобы просто поковыряться в \*.upt прошивках плееров на HiBy OS, сравнить
изменения в прошивках, можно не ходить в Linux/вирт. машину, а распаковывать
прошивки в Windows известным "редактором тем" (содержит портативные сборки
ubireader_extract_files и mkfs.ubifs) и сравнивать содержимое папок system
(различия файлов) разных прошивок в программе WinMerge. Я так делаю.
